# Chrono Trigger — Chapter 1: The Millennial Fair

A playable, in-browser recreation of the opening chapter of *Chrono Trigger*: Crono wakes up,
gets his allowance from Mom, walks north to Leene Square, bumps into Marle, plays the Fair,
and watches Lucca's Telepod tear a gate open in the middle of the exhibition.

**Play it:** https://trimcrae.github.io/Chrono-trigger/

Works on desktop (keyboard) and on phones (on-screen D-pad + A/B buttons).

## What's in it

- **Crono's room → Crono's house → Truce Village → Leene Square → Lucca's Telepod exhibit**,
  all walkable, with a follower party member, NPC chatter and scripted cutscenes.
- The opening beats: Mom's wake-up call, the 200 G allowance, the collision with Marle and her
  pendant, the Fair stalls, Leene's Bell, and the Telepod demonstration that ends the chapter.
- **Gato**, the singing robot, as an optional ATB battle (Attack / Tech / Item / Run, with
  Crono's Cyclone and Marle's Aura) that pays out 15 Silver Points.
- A chiptune soundtrack and sound effects synthesised live with the Web Audio API.

## Controls

| Action | Keyboard | Touch |
| --- | --- | --- |
| Move | Arrow keys / WASD | D-pad |
| Talk, confirm, advance text | Z / Enter / Space | A |
| Run, cancel | X / Shift | B |
| Status screen | C / Esc | MENU |

Sound can be muted with the ♪ button; ⛶ goes fullscreen.

## How it's built

No build step, no dependencies, no external assets — just static files served straight from
GitHub Pages. Everything is drawn at runtime:

| File | Purpose |
| --- | --- |
| `index.html`, `style.css` | Page shell, canvas, and the touch control layout |
| `js/pix.js` | Procedural pixel art: characters, tiles and props drawn into offscreen canvases |
| `js/maps.js` | Tile grids, exits, NPCs and scenery for the five areas |
| `js/game.js` | Engine (movement, collision, camera, cutscene runner) and the chapter's story |
| `js/battle.js` | The ATB battle used for Gato |
| `js/ui.js` | Dialogue windows, choices and HUD |
| `js/audio.js` | Web Audio chiptune engine and sound effects |
| `js/input.js` | Keyboard plus an analog-ish touch D-pad and buttons |
| `js/assets.js` | Optional sprite-sheet loader that overrides the drawn art |

The world renders into a 256×224 pixel buffer (SNES-ish) that is scaled to fit the screen, while
text is drawn on top at device resolution so it stays crisp on phones.

Run it locally with any static server:

```sh
python3 -m http.server 8000   # then open http://localhost:8000
```

## Tests

Three scripted browser tests drive the real game through the real keyboard path.
They need a static server on the given URL and `npm i playwright`:

```sh
node tools/playthrough.mjs http://localhost:8000   # the chapter, start to finish
node tools/edgecases.mjs   http://localhost:8000   # everything a straight run misses
node tools/battle.mjs      http://localhost:8000   # the ATB battle, every command and outcome
```

`playthrough.mjs` plays the chapter — title, allowance, the walk to Leene Square,
the collision with Marle, a purchase, the Gato battle, the Telepod and the gate —
asserting on story flags at each beat and shooting every scene to `/tmp/play`. It
routes with breadth-first search over the game's own collision, so a wandering
crowd cannot wedge it.

`edgecases.mjs` covers what that never reaches: every NPC on every map, every
piece of scenery with a description, every exit, Leene's Bell and the Telepod
pads, both answers to every prompt, the gate with and without the pendant, the
status menu, the sound button, a run on the built-in art via `?noassets=1`, and a
restart from the ending checking that gold, silver, flags and items all reset.

`battle.mjs` drives the ATB battle through its own menus: Attack, Tech, Item and
Run, backing out of a submenu, the not-enough-MP guard, and all three outcomes —
including losing, which a normal playthrough never sees because the party wins
comfortably.

All three fail on a page error, a stall, or a step that never reaches the state
it expects, and each prints what it actually exercised. They read `window.__CT` /
`__CTDLG` / `__CTDBG`, the debug handles `js/game.js` already exposes; shared
plumbing lives in `tools/testkit.mjs`.

## Using your own art

The sprites and tiles are generated by `js/pix.js`, and that art is a *fallback*.
Point `assets/manifest.json` at a sprite sheet and the engine slices it at boot
and renders those pixels instead — per character, per tile, or per prop, so you
can replace one thing at a time. `assets/README.md` documents the layout, and
`assets/templates/` contains dumps of the built-in art at the exact cell sizes.
Load the page with `?noassets=1` to force the built-in art and compare.

The art the game ships with is drawn by hand in `tools/art/` and built into
`assets/packs/` by `tools/sprite_pipeline.py` — `sprites.py` for the sixteen
frames of each character, `tiles.py` for the thirty-one map tiles. The
sprites are original pixel art written to sit in the same visual register as
SNES-era overworld art — a head about a third of the body, a dark warm outline
rather than black, one light source, small dark eyes, and a four frame walk with
a one pixel bob. A shared body carries per-character hair, palettes and props
(Crono's headband and back-slung katana, Marle's ponytail and pendant, Lucca's
helmet and glasses), so the whole cast stays consistent. Tiles come in two kinds:
ground that repeats across a whole screen — grass, earth, pavement, water,
carpet — is textured from a fixed seed, because hand-placed noise reads as a
stamped motif the moment it tiles; everything with a shape is written out as a
grid. The oversized props — Gato, Leene's Bell, the gate, a balloon — live in
`tools/art/props.py`.

```sh
python3 tools/sprite_pipeline.py build    # redraw assets/packs/ and update the manifest
python3 tools/sprite_pipeline.py verify   # check the sheet against the manifest
```

The pipeline can also assemble a sheet from an openly licensed pack fetched off
the internet — `assets/sources.json` takes the URLs and the `[col, row]` cells to
cut, each download pinned by SHA-256, and `.github/workflows/sprites.yml` runs
the fetch on an Actions runner. Any pack must declare an SPDX license to build at
all.

*Chrono Trigger*'s own sprites belong to Square Enix and are not redistributable,
so they are not fetched, traced or reproduced here — the art above is drawn to
evoke the era's style, not to copy the game's pixels.
